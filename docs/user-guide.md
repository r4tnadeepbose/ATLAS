# ATLAS User Guide

## 1. First access

1. Open the UI (`http://localhost:5173` locally, `http://localhost:8080` in
   Compose).
2. If the instance has no users, use **workspace bootstrap**: organization name,
   your name, email and a 12+ character password. This creates the organization
   and a Super Administrator.
3. Later users are created by an administrator under **User Management**; roles
   determine what each person sees and can do.
4. Enable MFA in **Organization Settings → Account security** (authenticator app,
   then confirm a code).

## 2. Reading the Command Center

- Six headline metrics: assets, microservices, APIs, open findings, posture and
  MTTD. Each is clickable.
- **Posture** is `100 − average open finding risk`. Lower is worse.
- **Severity distribution**, **posture trend**, **discovery timeline**, **asset
  exposure**, **risk by business unit**, **top vulnerable services**, **SBOM
  coverage**, **API posture**, **remediation progress** and **recent activity**
  all come from live records.
- In a demo environment a banner states that data is synthetic.

## 3. Asset Intelligence

- Filter by exposure, criticality, environment and free text.
- Open an asset to see classification, network services, technologies,
  certificates, linked findings and current risk.
- Register assets manually or let authorized assessments discover them.

## 4. Microservice Map

- **Relationship map** shows services and external dependencies. Node colour is
  risk level; badges show open finding counts.
- Click a node to focus; double-click to open the service record.
- Filter by business unit, risk level, vulnerability status; toggle external
  dependencies.
- The **inventory** tab provides searchable ownership and risk data.

## 5. SBOM Intelligence

1. **Upload SBOM** → choose a CycloneDX JSON/XML or SPDX JSON/tag-value file.
2. Optionally attach it to a microservice and a version label.
3. ATLAS parses components, then correlation runs in the background:
   offline matching against stored intelligence plus OSV query.
4. Findings are generated for vulnerable components of linked services.
5. Open the document to inspect components, vulnerabilities, scan history, and
   export a CSV. Use **Compare** to diff two versions and **Re-analyze** after
   intelligence updates.
6. **Syft generation** is available from the API (`POST /sbom/generate`) when Syft
   is installed on the API host.

Supported purl ecosystems: npm, PyPI, Maven, RubyGems, Go, crates.io, NuGet,
Debian, RPM, Alpine, Docker.

## 6. Vulnerabilities

- **Findings** tab: filter by severity, status, category; sort by risk or date;
  export CSV.
- Row opens the finding detail:
  - Overview: description, remediation, asset/service context, SLA.
  - Change status with a note (every transition is historicized).
  - Assign an owner (where your role allows).
  - Attach evidence (redacted context) and comment.
  - Run **AI triage**; results are advisory and labelled by provider.
- **Intelligence records** tab browses global CVE/OSV records and exploitation
  flags.

## 7. AI Triage

- The queue lists open findings without analysis.
- **Analyze** one finding or **Triage next 10**.
- When no model is configured, results are generated by the deterministic
  heuristic engine and labelled `heuristic`.
- Every result shows confidence, false-positive likelihood, recommendation,
  latency and token usage. AI never changes severity, closes findings or executes
  remediation.

## 8. Attack Surface and Scan Management

Authorized assessments only.

1. **New assessment** → name, scan type, target, authorized scope (domains), and
   authorization reference.
2. The backend validates scope; out-of-scope targets are rejected.
3. The job runs in the background. Detail shows progress, logs, result artefacts
   and generated findings.
4. Cancel queued/running jobs from the list.
5. **Scan Management** holds cron schedules and adapter availability. Schedules
   are queued by Celery beat; their scope is revalidated at execution.

## 9. API Inventory

- **Import specification** (OpenAPI 3.x / Swagger 2.0, JSON/YAML).
- ATLAS creates the API, endpoints and authentication metadata, then runs static
  checks: missing authentication, weak authorization, insecure transport,
  exposed documentation, deprecated endpoints, sensitive paths.
- Open an API to review endpoints and issues, re-run checks, or export CSV.

## 10. Data Classification

1. **Analyze content** → paste configuration/log/request samples.
2. Optionally link an asset or microservice and set a source label.
3. ATLAS applies regex + entropy rules, stores redacted samples, and creates
   findings for critical/high detections.
4. Manage rules under the **Detection rules** tab; install defaults if empty.

Never paste live production secrets. Values are masked, but the analysis is
intended for controlled samples.

## 11. Risk Management

- **Recompute risks** refreshes assessments and service/asset risk.
- The register shows score, band, business unit, owner, status and deadline.
- **Accept** records a residual-risk exception with justification and optional
  expiry; the finding becomes `risk_accepted`.
- **Remediation tasks** are generated per assessed finding; completing a task
  resolves the linked finding.

## 12. Notifications and Reports

- Notification center shows severity-tagged alerts with read state; routing rules
  control channels and dedup windows.
- Reports: choose a type and PDF/CSV/JSON, generate, then download. Every report
  is rendered from current organization data.

## 13. Administration

- **Users**: invite, deactivate, change role. You cannot change your own role or
  deactivate yourself.
- **RBAC**: review built-in roles and the permission catalog.
- **Integrations**: adapter status, enable/disable, test and JSON configuration.
- **Organization Settings**: organization name, teams, runtime configuration,
  MFA and password.
- **System Configuration**: tenant JSON settings, background jobs, audit trail and
  metric snapshot.

## 14. Role expectations

| Role | Typical use |
| --- | --- |
| Super Administrator | Everything, including users and settings |
| Security Administrator | Operate all security modules and integrations |
| SOC Analyst | Monitor, triage, run assessments, update risk |
| VAPT Analyst | Authorized testing, evidence, API inventory, reports |
| Developer | See assigned services, remediate and update findings |
| Executive | Posture, business risk, remediation rate and reports |
